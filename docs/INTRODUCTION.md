# 项目说明：为什么做 KVM-Wire

> 一句话：让**蓝牙键鼠绕过平板**，直接连到那台不方便搬动的台式机，从而在远程办公时保留全部专业快捷键。

## 1. 真实场景

有一类工作必须用**台式工作站**：

- 性能要求高：CAD / EDA / 3D / 视频剪辑 / 编译 / 仿真
- 外设固定：多显示器、采集卡、加密狗、专用串口设备
- 机器固定：放在公司工位、实验室机柜、机房，**不方便搬动，也不方便带出门**

但人需要出差、回家、去客户现场。为了轻便，通常只带：

- 一台平板电脑（iPad / Android / Windows 平板）
- 一把蓝牙键盘 + 一个蓝牙鼠标

直觉做法是：**平板连上蓝牙键鼠，再用远程软件（UU、向日葵、ToDesk、RDP、VNC）连回台式机**。

这个做法能“看到画面、能打字”，但一旦涉及专业操作就会出问题。

## 2. 现有做法的痛点

### 2.1 平板成了 HID 主机，快捷键先被平板吃掉

键鼠连到平板后，按键首先进入**平板的操作系统**：

- `Win` 键被平板/远程软件拦截，打开的是平板的开始菜单或远程软件菜单
- `Alt + Tab`、`Ctrl + Shift + Esc`、`Win + L`、`Ctrl + Alt + Del` 等组合被平板系统或远程软件占用
- 平板软键盘没有 `Insert`、`Delete`、`F1~F12`、`Pause`、`ScrollLock`、小键盘
- `Fn` 层、媒体键、键盘宏被平板重新解释
- 中文/英文输入法、Dead key、AltGr 在平板侧先处理一遍，到电脑上已经变形

### 2.2 远程软件转发的是“平板的键盘事件”，不是原始 HID

远程软件拿到的是平板 OS 已经处理过的按键，再封装成自己的协议发到电脑。
这意味着：

- 电脑收到的不是键盘原始的 **HID usage + 修饰键位图**
- 组合键的按下/抬起顺序可能被合并、丢失或重排
- 长按重复、Ctrl 粘滞、Shift 选中、鼠标侧键/横向滚轮经常出问题
- 不同远程软件行为不一致，换一个软件快捷键又失效

对于 IDE、CAD、EDA、终端、财务软件、游戏来说，**快捷键就是生产力**，这类问题直接让方案不可用。

### 2.3 硬件 KVM 也不合适

传统 KVM 需要把显示线、USB 线都接到切换器上：

- 台式机在机房/工位，走线困难
- 出差时不可能带着 KVM 和一堆线
- 只能本地切换，不能跨公网

## 3. 我们的做法：让键鼠“绕过平板”

KVM-Wire 把输入链路从“平板中转”改成“设备直连电脑”：

```
蓝牙键鼠 ──BLE──> ESP32-S3 ──WiFi──> 台式机上的 Agent ──SendInput──> 本机
                                      ▲
平板（只负责显示/网络） ──远程画面──────┘
```

- 蓝牙键鼠连接的是 **ESP32-S3**，不是平板
- ESP32 把键盘/鼠标的**原始 HID 报告**通过 WiFi 发给台式机
- 台式机上的 Agent 用 Windows `SendInput` 注入，系统认为这就是本地键鼠
- 平板只负责“看画面”，**不参与输入路径**

### 为什么这样能保留快捷键

1. 传输的是 HID 层数据：usage page、usage id、modifier 位图、鼠标按键/位移/滚轮
2. 不经过平板 OS 的键盘映射、输入法、快捷键拦截
3. PC 端以本机硬件输入的方式注入，IDE/CAD/终端拿到的是正常 `WM_KEYDOWN` / `WM_KEYUP`
4. `Ctrl`、`Shift`、`Alt`、`Win` 的按下/抬起严格按物理状态同步，不会“粘键”
5. 鼠标侧键、横向滚轮、中键、双击、拖拽都按原始报告还原

## 4. 数据流与延迟

```
键盘/鼠标
  │ BLE HID report（7.5ms 连接间隔）
  ▼
ESP32-S3
  │ 合并鼠标 8ms，封装 KVM-Wire 帧
  ├─ 局域网：UDP 直连（3~15ms）
  └─ 广域网：TLS 到中继（30~60ms）
  ▼
PC Agent
  │ 解析 HID → VK/扫描码
  ▼
SendInput（<1ms）
```

实测（深圳 → 广州中继 → 深圳）：

| 场景 | RTT |
|------|-----|
| 局域网直连 | 3~15ms |
| 广域网空闲 | 30~50ms |
| 广域网鼠标持续移动 | 60~125ms |

打字、IDE、终端、CAD 都可用；对帧级竞技游戏不推荐。

## 5. 适用人群

- **工程师 / 设计师**：出差用平板 + 键鼠操作公司的台式工作站
- **运维 / 实验室**：机柜里的机器不方便接显示器，用平板做控制台
- **多机用户**：一套键鼠，通过网页切换不同设备
- **远程办公**：公司电脑不能带走，但需要完整的本地键盘体验
- **演示 / 教学**：讲师用自己的键鼠操作固定演示机

## 6. 与其它方案对比

| 方案 | 快捷键 | 便携 | 需要台式机装软件 | 说明 |
|------|--------|------|------------------|------|
| 平板直连键鼠 + 远程软件 | ❌ 常被拦截/变形 | ✅ | ✅ | 输入先经过平板 OS |
| 硬件 KVM | ✅ | ❌ 要带切换器和线 | ❌ | 只能本地 |
| 软件 KVM（Sunshine/Parsec） | ✅ | ✅ | ✅ | 依赖 host 端软件与显卡编码 |
| USB/IP | ✅ | 一般 | ✅ 驱动 | 网络要求高，配置复杂 |
| **KVM-Wire** | ✅ | ✅ 只需一个小盒子 | ✅ 一个轻量 Agent | 输入走 HID 直通，显示可用任意远程软件 |

KVM-Wire 不替代远程画面软件：**画面继续用你习惯的 UU / RDP / 向日葵，键鼠走 KVM-Wire**。

## 7. 功能

- BLE HID Host：直接连接 BLE 键盘/鼠标，保存配对信息
- 网页配网：开放热点 `KVM-Setup-XXXX`，连上自动弹配置页（Captive Portal）
- 局域网自动发现：PC 端广播发现，点击确认连接
- 广域网中继：设备与 PC 都主动连 TLS 中继，按 device_id 配对
- Windows 注入：绝对坐标跟踪、多显示器、滚轮/横向滚轮、按键重复、看门狗释放
- 自动重连：键鼠休眠后按已保存设备/名字扫描重连
- 低延迟：TCP_NODELAY、5ms 读超时、BLE 7.5ms、鼠标 8ms 合并

## 8. 安全模型

- 局域网：UDP 明文 + 16 位十六进制共享 token，**不要暴露 8766 到公网**
- 广域网：TLS（自签 CA）+ 设备密钥/客户端密钥；中继只转发，不解析键鼠内容
- 建议：密钥随机生成、定期轮换、中继使用独立用户与目录、限制来源 IP

## 9. 限制与边界

- **安全桌面**：Windows 登录界面、锁屏、UAC 弹窗、`Ctrl+Alt+Del` 属于 Secure Desktop，
  `SendInput` 无法注入。需要配合自动登录、远程软件或现场操作。
- **BIOS / POST**：Agent 运行在操作系统内，进系统前无法使用。
- **仅 Windows**：当前注入端只支持 Windows（`SendInput`）。
- **BLE 兼容性**：部分 BLE 5.0 设备在 S3 控制器上会被拒绝，固件强制 BLE 4.2。
- **随机地址**：部分键鼠使用 RPA，地址会变；已做按名字/已保存设备扫描重连。
- **延迟**：广域网经中继，受地理位置影响；P2P 打洞是后续方向。

## 10. 部署形态

```
出差：平板（UU/RDP 看画面） + 蓝牙键鼠 + ESP32（放家里/公司，USB 供电）
                              │
                        WiFi / 4G 热点
                              │
                        TLS 中继（可选，公网）
                              │
                        台式机 Agent
```

- 家里/公司：ESP32 接 5V USB，连 WiFi，键鼠配对一次
- 出门：平板远程看画面，键鼠直接连 ESP32
- 没有公网 IP 也能用：双方主动连中继
