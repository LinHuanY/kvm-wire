# KVM-Wire 协议 v1（LAN 阶段）

ESP32-S3 与 PC 注入端之间使用 **UDP 单播**，默认端口 `8765`。
帧采用小端序（little-endian），固定 21 字节头 + 0~255 字节负载。

设计目标：低延迟、无连接、可丢包、状态幂等（keyboard 发的是"当前按下集合"而不是增量）。

## 1. 帧格式

| 偏移 | 长度 | 字段 | 说明 |
|-----:|-----:|------|------|
| 0 | 1 | `magic0` | 固定 `0x4B` (`'K'`) |
| 1 | 1 | `magic1` | 固定 `0x56` (`'V'`) |
| 2 | 1 | `version` | 协议版本，当前 `1` |
| 3 | 1 | `type` | 消息类型，见下表 |
| 4 | 2 | `seq` | 发送序号，u16，回绕；用于丢包统计 |
| 6 | 1 | `flags` | 保留，当前为 0 |
| 7 | 1 | `reserved` | 保留，当前为 0 |
| 8 | 8 | `token` | 共享密钥（u64 LE），不匹配的包直接丢弃 |
| 16 | 4 | `dev_ms` | 发送端 uptime 毫秒（u32），用于时延统计 |
| 20 | 1 | `payload_len` | 负载长度（0~255） |
| 21 | n | `payload` | 负载 |

> token 只是"局域网内的弱口令过滤"，不是加密。不要在不可信网络上使用。

## 2. 消息类型

| 值 | 名称 | 方向 | 说明 |
|---:|------|------|------|
| 0x01 | `HELLO` | 设备 → PC | 上线/重连通告 |
| 0x02 | `KEY` | 设备 → PC | 键盘/消费类按键的**全量按下集合** |
| 0x03 | `MOUSE` | 设备 → PC | 鼠标状态（累计位移、按键） |
| 0x04 | `PING` | PC → 设备 | 心跳，负载携带 PC 时间戳 |
| 0x05 | `PONG` | 设备 → PC | 心跳应答，回显 PC 时间戳 |
| 0x06 | `CMD` | PC → 设备 | 控制命令 |
| 0x07 | `STATUS` | 设备 → PC | 电池/连接状态 |
| 0x08 | `RELEASE` | 设备 → PC | 立即释放所有按键与鼠标键 |
| 0x09 | `DISCOVER` | PC → 设备 | 广播发现设备，设备回 HELLO |
| 0x0A | `KEEPALIVE` | 设备 → PC | 空闲时保活，避免 PC 端看门狗误判 |
| 0x10~0x1F | 预留 | — | 广域网中继/会话控制（见 [wan.md](wan.md)） |

### 2.1 HELLO (0x01)

| 长度 | 字段 |
|-----:|------|
| 1 | `proto_major` = 1 |
| 1 | `fw_major` |
| 1 | `fw_minor` |
| 1 | `caps`：bit0=键盘, bit1=鼠标, bit2=消费类 |
| 6 | `mac`（ESP32 的 STA MAC，小端字节序无效，按字节数组原样） |
| n | `name`：UTF-8 设备名，不带 `\0` |

PC 收到 HELLO 后重置按键状态并打印设备信息。

### 2.2 KEY (0x02)

| 长度 | 字段 |
|-----:|------|
| 1 | `page`：`0x07`=Keyboard/Keypad，`0x0C`=Consumer |
| 1 | `mods`：HID 修饰键位图（仅 page 0x07 有效） |
| 1 | `count`：后面 usage 的个数，0~12 |
| 2×count | `usages[]`：u16 HID usage id |

`mods` 位定义（与 USB HID 一致）：

| bit | 修饰键 | bit | 修饰键 |
|----:|--------|----:|--------|
| 0 | Left Ctrl | 4 | Right Ctrl |
| 1 | Left Shift | 5 | Right Shift |
| 2 | Left Alt | 6 | Right Alt |
| 3 | Left GUI | 7 | Right GUI |

语义：这是"当前按下的全部按键"快照，PC 端与本地状态做 diff 后产生 down/up 事件。
因此丢包后下一帧即可自愈；设备端每 500ms 会重发一次当前状态。

### 2.3 MOUSE (0x03)

| 长度 | 字段 |
|-----:|------|
| 1 | `buttons`：bit0=左, bit1=右, bit2=中, bit3=侧键1, bit4=侧键2 |
| 1 | `flags`：bit0=1 表示坐标是绝对值（0~32767），0 表示相对位移 |
| 2 | `dx` (i16) |
| 2 | `dy` (i16) |
| 2 | `wheel` (i16)：格数，一格 = Windows 的 120 |
| 2 | `pan` (i16)：横向滚轮格数 |

设备端把两次发送之间的位移累加，避免高频报告塞满队列。

### 2.4 PING (0x04) / PONG (0x05)

`PING` 负载：`u32 host_ms`（PC 单调时钟毫秒）。
`PONG` 负载：`u32 host_ms`（原样回显），`u32 dev_ms`（设备当前 uptime）。

PC 用 `recv_time - host_ms` 估算单程时延（时钟不同源，只能看趋势）。

### 2.5 CMD (0x06)

| 长度 | 字段 |
|-----:|------|
| 1 | `cmd`：1=RESYNC（重发按键状态）, 2=RELEASE_ALL, 3=SCAN（重新扫描蓝牙设备） |
| 1 | `arg`：保留 |

### 2.6 STATUS (0x07)

| 长度 | 字段 |
|-----:|------|
| 1 | `count` |
| 3×count | 每项：`cls`(1=键盘,2=鼠标,3=消费), `battery`(0~100，255=未知), `rssi`(i8) |

### 2.7 RELEASE (0x08)

无负载。PC 立即释放所有按键/鼠标键（设备检测到 BLE 断开时发送）。

### 2.8 DISCOVER (0x09) / 自动发现

PC 向局域网广播 `DISCOVER`（目标端口 **8766**，负载为空），设备收到后单播回一个 `HELLO`：

- 设备固定在 `CONFIG_KVM_DEVICE_PORT`（默认 **8766**）监听，PC 注入端默认监听 **8765**，两者不同；
- PC 广播目标：`255.255.255.255`、各网卡的 `/24` 定向广播、`127.0.0.1`（便于本机模拟器联调）；
- 设备对 DISCOVER **不校验 token**（LAN 内允许未知 PC 发现），回应里带自己的 token，用于 PC 端预填；
- 设备**不会**因为一次 DISCOVER 就切换当前主机，只有收到 `PING` 才锁定对端；
- 设备限速：最多每 500ms 回应一次。

PC 端拿到 HELLO 后展示「设备名 / IP:端口 / MAC / 固件 / token」，用户点击确认后才开始注入。

### 2.9 KEEPALIVE (0x0A)

无负载。设备在没有键鼠事件时每 1s 发一次，维持链路活跃。
PC 端看门狗默认 **3s**：超过 3s 没有任何有效帧才释放全部按键，避免「按住鼠标左键不动」被误判为断线。

## 3. 时序与可靠性

- 鼠标：设备端约每 8ms 汇总发送一次；PC 端 `--stats` 可看到 pps。
- 键盘：状态变化立即发送；另每 500ms 重发快照。
- 保活：设备空闲时每 1s 发 `KEEPALIVE`；PC 每 1s 发 `PING`，设备回 `PONG`。
- PC 端 3s 内没有收到任何有效帧 → 视为链路断开，**释放全部按键/鼠标键**并等待重连。
- 不重传、不排序。UDP 丢一帧只会造成一次位移/按键状态延迟，下一帧自愈。

## 4. 端口与防火墙

| 端 | 默认端口 | 用途 |
|----|---------|------|
| PC 注入端 | **8765/UDP** | 接收键鼠事件、PING、命令 |
| ESP32 设备 | **8766/UDP** | 监听 DISCOVER、接收 PING/CMD、发送事件 |
| 广域网中继 | 443/TLS | 预留，见 [wan.md](wan.md) |

- Windows 首次运行时如弹出防火墙提示，请允许「专用网络」；也可手动放行 UDP 8765 与 8766。
- 设备用 `KVM_DEVICE_PORT`、PC 用 `--device-port` 可改 8766，两边保持一致。
