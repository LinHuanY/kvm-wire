# 排错手册

## 1. 连上热点但打不开 192.168.4.1

- 确认连的是 `KVM-Setup-XXXX`，不是家里的 WiFi。
- 手机提示「此网络无互联网」时选择**保持连接**（iOS 点「继续使用」）。
- 浏览器地址栏输入 `http://192.168.4.1/`（不要用 https）。
- 看串口日志确认 AP 是否启动成功；若反复重启，多半是供电不足（换 USB 口/线）。
- 扫描 WiFi 时 ESP32 射频要切换信道，**网页可能短暂断开/转圈**，等几秒刷新即可（扫描完会自动回到原信道）。

## 2. 扫描不到蓝牙键鼠

- **先确认设备是 BLE 蓝牙，不是 2.4G USB 接收器**。带 USB 小接收器的键鼠是私有 2.4G 协议，ESP32 蓝牙永远搜不到，需要 USB Host 方案（后续阶段）。
- 键鼠要进入**配对模式**：通常长按蓝牙键 3~5 秒，指示灯快闪。
- 如果它已经连着手机/电脑，先断开或关掉那台设备的蓝牙。
- 天线接了吗？（WROOM-1U 必须接外置天线）
- 扫描列表默认 8 秒，设备多时多扫几次。

## 3. 能连上但电脑没反应

先确认 BLE 是否真的连上（网页「已连接」/ 串口 `kvm_ble: 已连接 ... usage=`）。
注意两个已踩过的坑：

- **RK-100 显示为 `RK-100-3.0`**：那是经典蓝牙（BTHENUM），ESP32-S3 只支持 BLE，连不上。
  键盘必须切到 **5.0 / BLE 模式**。
- **键鼠已连在 Windows 上**：BLE 外设被一台主机连着时不会接受第二个主机。
  需要先在「设置 → 蓝牙和其他设备」里删除设备，或关闭电脑蓝牙，再让键鼠进入配对模式。
- 连接时串口出现 `OPEN failed: 0x85` / `opcode=0x2043 Cmd Disallowed`：这是 BLE 5.0 扩展连接被 S3 控制器拒绝，
  本工程已固定为 **BLE 4.2 传统连接**（`sdkconfig.defaults` 里 `CONFIG_BT_BLE_50_FEATURES_SUPPORTED=n`）。

按顺序查：

1. **PC 端有没有收到包**：`python kvm_agent.py --dry-run --verbose`，看是否打印 `[link] 设备上线` 和 `KEY/MOUSE`。
   - 没有 → 网络/token 问题，见第 4 条。
2. **BLE 有没有收到报告**：串口 `idf.py monitor`，把日志级别调到 Debug：
   ```
   idf.py monitor
   # 在 monitor 里输入：
   log_level kvm_ble 4
   ```
   按键时应该看到 `INPUT: KEYBOARD ... data=[...]`。没有的话是**通知没订阅上**，通常是配对/加密问题：
   - 网页断开设备 → 忘记该设备（恢复出厂）→ 重新配对；
   - `idf.py menuconfig` → KVM Bridge → 关闭 `KVM_BLE_BOND` 再试；
   - 个别键盘需要先按一下键唤醒。
3. 网页「已连接」有设备但电量 `?`，通常说明电池服务不存在，不影响使用。

## 4. token / IP 不对

- 固件默认 token `0123456789abcdef`；PC 端 `python kvm_agent.py --token 0123456789abcdef`。
- 两边不一致时，PC 端会打印 `token 不匹配`，固件端收到的包会被丢弃。
- 用 `--scan` 或 GUI 连接时，会**自动使用设备上报的 token**，一般不用手填。
- 电脑 IP 填错时，可把网页「IP 地址」留空 → 固件向 `255.255.255.255` 广播，agent 回包后自动锁定。
- Windows 防火墙首次会弹窗，勾选「专用网络」；也可手动放行 UDP 8765 和 8766。

## 4.1 PC 发现不到设备（--scan / GUI 列表为空）

按顺序排查：

1. 设备和电脑是否在**同一网段**？跨网段/AP 隔离（路由器「访客网络」「AP 隔离」）会挡住广播。
2. 设备网页里 WiFi 是否已连上（STA 有 IP）？只有 AP 没连家里 WiFi 时，PC 找不到它。
3. Windows 防火墙：允许 `python.exe` 的专用网络入站 UDP；或临时关闭防火墙测试。
4. 设备端口：默认 8766，PC 端 `--device-port` 要一致（`KVM_DEVICE_PORT` 改过的话）。
5. 多网卡电脑：程序会向每个网卡的 `/24` 广播地址各发一次；如果设备在 `/16` 或其它掩码网段，请直接用 `--peer IP:8766`。
6. 本机模拟器联调时，模拟器要监听 8766：`python simulate.py --serve --token ...`。

## 4.2 保存 WiFi 时提示「保存失败: Failed to fetch」

- 原因：ESP32 只有一套 2.4G 射频。保存后 STA 要切到目标 AP 的信道，AP 跟着换信道，
  浏览器的 TCP 连接被切断，`fetch` 就报 `Failed to fetch`。**配置通常已经写进 NVS 了**。
- 固件已改为「先回 HTTP 响应，600ms 后再切信道」，正常情况下应显示「已保存，正在切换网络」。
- 页面断开后等 5~10 秒，重新连 `KVM-Setup-XXXX` 或刷新，状态区会显示 STA 是否拿到 IP。
- 串口出现 `WiFi 断开 (reason=15)` 是 4 次握手超时：密码不对或 AP 拒绝，重新核对密码。
  连续失败会每 5 秒重试一次，期间 AP 会反复抖，建议先在网页里改对密码。

## 5. 鼠标飘/卡顿

- 默认 `track` 模式（读光标位置 + 绝对定位）不受 Windows 指针加速影响；`relative` 模式会受「提高指针精确度」影响。
- 灵敏度：`--scale 1.5` 或 GUI 里的「灵敏度」。
- 2.4GHz 拥堵：换 WiFi 信道（路由器 1/6/11）、远离 USB3.0 硬盘盒、给模块接好天线。
- 蓝牙与 WiFi 共存会有调度抖动，属正常现象；可把电脑和 ESP32 放近一点。

## 6. 按键卡住 / 鼠标一直按着

- PC 端有 3 秒看门狗（设备每秒发 KEEPALIVE，正常不会触发）：收不到数据会自动释放全部按键。
- 网页点「释放全部按键」，GUI 里也有同名按钮，或重启 agent（退出时会释放）。
- 实在不行：Windows 按一下本地键盘的 Ctrl/Shift 通常能解除修饰键卡住。

## 7. Ctrl+Alt+Delete、UAC、锁屏没反应

Windows 的安全桌面（Secure Desktop）不接受 `SendInput` 注入，这是系统限制，不是程序 bug。需要这些场景必须用 USB HID 硬件方案（后续阶段）。

## 8. 烧录失败

- 报 `Failed to connect`：按住 BOOT 键再点复位/上电，进入下载模式后重试。
- 确认端口号：设备管理器看 CH340/CP210x/ESP32-S3 的 COM 口。
- `idf.py: command not found`：先执行 `esp-idf\export.ps1`。
- 编译报组件找不到（例如 mDNS）：确认用的是 **IDF 5.5.5**，不是 5.1/6.0 的残缺安装。

## 9. 恢复出厂

- 长按 BOOT 键 5 秒 → 重启并清空 WiFi/token/配对信息。
- 或网页「系统 → 恢复出厂设置」。
